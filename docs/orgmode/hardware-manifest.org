* Purpose

This document is the *hardware contract* for hzArchiso machine profiles: exact
(or option-matrix) hardware where known, why packages/kernel pins exist, and
what must be verified on first boot. Installer deltas and linux-rg overlays
must stay consistent with these tables.

Live PCI/USB IDs for a given unit are recorded after install under the
=Live probe= sections (fill on the target machine; CI does not invent them).

Related:

- Installer packages: =installer/hz-install-tui/install/packages.go=
- Profile UX: [[file:profiles.org][profiles.org]], [[file:installer.org][installer.org]]
- Kernel overlays (linux-rg): =docs/rgSURFLat-*.org=, =docs/rgx1gen11-*.org=,
  =docs/rgam5terra-*.org= in the linux-rg repository

Dell Setup and Specifications (official option matrix) list multiple *factory
CPU SKUs* on the same motherboard family. The profile optimizes for the common
*U15* Alder Lake–U / Iris Xe class; P28 “P” SKUs remain Intel iGPU + SOF and
are in-scope for the same package/kernel pins.

** Fingerprint (optional SKU)

Many Latitude 7430 builds include a fingerprint reader that needs a *vendor
TOD* blob under libfprint (historically Broadcom on Dell business lines).

| Layer | Package |
|-------|---------|
| Userspace daemon | =fprintd= (official repos — always in profile delta) |
| Proprietary TOD | =libfprint-2-tod1-broadcom= or successor (*AUR / vendor*; **not** a hard gate) |

Install TOD only if =lsusb= shows the reader and =fprintd= cannot enroll.

** Power / sleep rationale

Modern Latitude firmware often prefers *S0ix* (modern standby) over legacy S3.
Hibernation is *best-effort* until validated on the unit’s BIOS revision.
Installer keeps TLP + thermald; do not enable hibernation blindly.

** Package / kernel rationale map

| Hardware need | Installer / policy | Kernel / overlay |
|---------------|--------------------|------------------|
| Alder Lake CPU errata | =intel-ucode= | Arch/linux-rg base |
| Iris Xe display + Vulkan | =mesa=, =vulkan-intel= | =DRM_I915=, =DRM_XE= |
| VA-API media | =intel-media-driver=, =libva-utils= | media drivers in base |
| SOF audio | =sof-firmware= | SOF Intel TGL/ADL pins |
| AX211 Wi-Fi / BT | =linux-firmware=, =wireless-regdb= | =IWLWIFI=, =btusb=; modprobe =rgSURFLat-iwlwifi.conf= |
| Battery / thermals | =tlp=, =tlp-rdw=, =thermald= | intel_pstate, intel_idle, Dell sensors |
| Dell platform | (kernel) | =CONFIG_DELL_*= in =rgSURFLat.config= |
| Fingerprint enroll | =fprintd= (+ optional AUR TOD) | USB HID / vendor |
| Explicitly *out* | No =amd-ucode=, no NVIDIA, no =tuned= | No znver5 / AMD dGPU patches |

** Live probe checklist (run on the unit)

#+begin_src shell
sudo dmidecode -s system-product-name
sudo dmidecode -s system-version
sudo dmidecode -s system-serial-number
lscpu | sed -n '1,20p'
lspci -nnk | rg -i 'vga|display|network|audio|thunderbolt|nvm'
lsusb
journalctl -b -k | rg -i 'iwlwifi|i915|sof|dell|thunderbolt|mei'
#+end_src

Record outputs in the “This unit” table above or in linux-rg
=docs/rgSURFLat-targets.org=.

* Maintenance

When hardware changes (RAM upgrade, WLAN swap, different Latitude CPU SKU):

1. Update the “This unit” table (rgSURFLat) or linux-rg targets.org.
2. Adjust package deltas only if a *new class* of device appears (e.g. discrete
   GPU — would need a new profile, not a silent delta).
3. Re-run =make tui-check= and linux-rg =scripts/linux-rg-profile-selftest=.
