* About
This is a custom Arch Linux live USB for setting up encrypted machine
installations. The live environment boots into a Sway-capable system with
PipeWire, wlroots desktop portals, rescue tooling, and a terminal installer
named ~hz-install-tui~.

The installer is intentionally a TUI instead of a graphical installer. It
collects the install choices, reviews the destructive disk plan, asks for an
exact disk confirmation, then hands the generated configuration to
~archinstall~. The shell backend ~hz-install~ remains available as a scriptable
fallback.

#+BEGIN_QUOTE
hzlinarch=hzlinarch

^-- USERNAME=PASSWORD
#+END_QUOTE

The live greeter is ~greetd~ with ~tuigreet~. If the greeter is unavailable on
specific hardware, switch to another TTY with ~CTRL-ALT-F3~, log in with the
credentials above, and run ~sway~.

Target profiles are selected with ~--profile~:

- ~rgx1gen11~ keeps the ThinkPad laptop defaults and remains the default when
  no profile is specified.
- ~rgam5terra~ selects the Terra AM5 desktop target with AMD microcode,
  NVIDIA open DKMS drivers, NVIDIA userspace/OpenCL tooling, and tuned. It
  omits laptop-only target packages such as ~tlp~, ~tlp-rdw~, and ~thermald~.
  Install kernels are stock ~linux~ and ~linux-lts~ (enough for Terra to boot
  and install without a custom kernel package).

** Best path (dual Intel+AMD live media, Terra boot, 16GB USB, elja)

Decision summary for bootable installer media aimed at the Terra AM5 machine
described in the ~linux-rg~ tree, while remaining useful on Intel x86_64 boxes
(e.g. ~rgx1gen11~ ThinkPad) from the same 16GB stick.

*Current deliverable (no Arch on elja host):* a normal hzArchiso ISO with stock
kernels only. Do *not* require ~linux-rg~ packages in ~aurpkgs.txt~ or the
installer until an Arch-capable environment can produce them (elja login/compute
images are not Arch; full ~makepkg~ of ~linux-rg~ is deferred). Terra still
boots and installs via ~--profile rgam5terra~ on ~linux~ / ~linux-lts~ with
~amd-ucode~ and NVIDIA open DKMS.

| Topic | Choice |
| Live ISO architecture | ~x86_64~ only (no aarch64/ARM ISO) |
| Dual-vendor hardware | Ship both ~intel-ucode~ and ~amd-ucode~; EFI/syslinux/GRUB early-load *both* microcode images before the stock live ~initramfs-linux.img~ |
| Live + install kernels (now) | Stock Arch ~linux~ and ~linux-lts~ (generic modular). Live boot entry is always ~vmlinuz-linux~ / ~initramfs-linux.img~, not an AMD-only ISA build |
| Terra install profile | ~hz-install --profile rgam5terra~ adds ~amd-ucode~, ~nvidia-open-dkms~, ~nvidia-utils~, ~nvidia-settings~, ~opencl-nvidia~, ~tuned~, ~tuned-ppd~; drops laptop-only ~tlp~ / ~thermald~ |
| ~linux-rg~ (deferred) | Prefer later: build from the ~linux-rg~ tree with ~LINUX_RG_PROFILE=rgam5terra~ on an Arch host/container, drop packages into ~HZARCHISO_PREBUILT_DIR~, add ~linux-rg~ / ~linux-rg-headers~ to ~aurpkgs.txt~ and the Terra installer kernel list. Not required for first Terra boot |
| Primary builder | Prefer any Arch host with ~mkarchiso~. On elja: interactive ~srun~ from a ~tmux~ session, then Arch via ~podman run … archlinux:base-devel~ (privileged) for ~make aur-repo~ / ~make build~ — host packages alone are insufficient |
| USB target | Aim ISO under ~14GB~ so a 16GB stick has headroom; artifacts under ~out/~ |

** Methodology
The profile uses the standard ~archiso~ workflow. Daily-driver packages from
official Arch repositories and the local AUR/custom repository are baked into
the ISO so the live system is useful before installation. The build-time custom
repository is named ~hzarchiso~ and is mounted at ~file:///repo/hzarchiso~.

** Software Included
The exact live package list is in ~hzLinux/packages.x86_64~. The installed
system package set is rendered by ~hzLinux/airootfs/usr/local/bin/hz-install~
into the ~archinstall~ JSON files.

The current profile emphasizes:

- encrypted Btrfs install flow with ~linux~ and ~linux-lts~
- Sway, Waybar, foot, fuzzel, greetd, and tuigreet
- PipeWire, WirePlumber, ~xdg-desktop-portal~, and
  ~xdg-desktop-portal-wlr~
- screenshot and recording tools: grim-git, slurp-git, satty, wf-recorder,
  wl-clipboard, cliphist, OBS Studio, Kooha, and v4l2loopback
- browsers, office, and knowledge work: Firefox, Chromium, Vivaldi,
  LibreOffice, Obsidian, Zathura
- media and communication: VLC, Spotify, Element, Discord, Telegram
- file management and device integration: Thunar, Engrampa, GVFS MTP, Android
  tools, Flatpak
- laptop/rescue tooling: NetworkManager, tailscale, fwupd, smartmontools,
  nvme-cli, tlp, thermald, zram-generator
- rgam5terra target tooling: amd-ucode, nvidia-open-dkms, nvidia-utils,
  nvidia-settings, opencl-nvidia, tuned, tuned-ppd
- bootstrap and development tooling: chezmoi, age, pass, git, openssh, gh,
  glab, podman, build/debug tools
- AUR/local payload: linux-nitrous, linux-nitrous-headers, Enpass, pCloud,
  Windscribe, Cryptomator, gnome-encfs-manager, yay, rtl88xxau DKMS, and the
  existing git variants for Sway/Wayland helper tools

* Installer
Run the TUI from the live environment:

#+begin_src bash
hz-install-tui
#+end_src

Render the same install JSON without installing:

#+begin_src bash
hz-install-tui --dry-run \
  --profile rgx1gen11 \
  --target-disk /dev/nvme0n1 \
  --hostname rgx1gen11 \
  --username rgoswami \
  --timezone America/Chicago \
  --console-keymap us \
  --chezmoi-key-layout colemak \
  --machine-name rgx1gen11 \
  --output-dir /tmp/hz-install
#+end_src

The fallback backend can be used directly:

#+begin_src bash
hz-install --dry-run --target-disk /dev/nvme0n1 --output-dir /tmp/hz-install
#+end_src

Render the Terra target profile:

#+begin_src bash
hz-install --dry-run \
  --profile rgam5terra \
  --target-disk /dev/nvme0n1 \
  --output-dir /tmp/hz-install-rgam5terra
#+end_src

Non-dry-run installs require root, a whole-disk block device, exact disk
confirmation, root/user passwords, and a disk encryption password.

* Build Steps
Build and validation should run on an Arch builder or in an Arch container:

#+begin_src bash
sudo install -d -o "$(id -u)" -g "$(id -g)" /repo/hzarchiso
HZARCHISO_INSTALL_BUILT=1 make aur-repo
make tui-check
make check
make repo-check
make build
#+end_src

The ~aur-repo~ target builds package bases from AUR metadata, adds direct-clone
legacy AUR bases when the RPC result is unavailable, copies packages supplied by
~HZARCHISO_PREBUILT_DIR~ (optional; used for binary-only AUR packages), and
writes a pacman repository named ~hzarchiso~. The ~build~ target verifies that
this repository contains every package in ~aurpkgs.txt~ before running
~mkarchiso~.

The AUR build tree defaults to ~/repo/hzarchiso/build~ so large packages such as
~linux-nitrous~ use the same mounted filesystem as the local package repository.
Set ~HZARCHISO_BUILD_DIR~ when the repository path is not on a roomy filesystem.

Containerized builds need a writable ~/repo/hzarchiso~ and a non-root user for
~makepkg~ (use this on elja; the host OS is not Arch):

#+begin_src bash
docker run --rm --privileged \
  -v "$PWD:/work" \
  -v /path/to/hzarchiso-repo:/repo/hzarchiso \
  -w /work \
  archlinux:base-devel \
  bash -lc '
    pacman -Sy --noconfirm archiso base-devel go jq make sudo git
    useradd -m builder
    printf "builder ALL=(ALL) NOPASSWD: ALL\n" >/etc/sudoers.d/builder
    chown -R builder:builder /repo/hzarchiso /work
    sudo -u builder HZARCHISO_INSTALL_BUILT=1 make aur-repo
    make build
    ls -lh out/
  '
#+end_src

The ~build~ target compiles ~hz-install-tui~ into
~hzLinux/airootfs/usr/local/bin/hz-install-tui~, validates the profile, and runs
~mkarchiso~. ISO images land under ~out/~ (default ~outDir~ in the Makefile).

On the live USB, install Terra with stock kernels:

#+begin_src bash
hz-install-tui --profile rgam5terra
# or
hz-install --profile rgam5terra --target-disk /dev/nvme0n1 …
#+end_src

** Elja (~srun~ + ~tmux~) procedure — normal ISO (no ~linux-rg~)

Login nodes (~slogin1.rhi.hi.is~, user ~rog32~ via ~ssh elja~) are not Arch
hosts and cannot run ~mkarchiso~ or AUR ~makepkg~ natively. Use an interactive
Slurm allocation and an Arch container (~podman~ is available). Control the long
session from ~tmux~ so disconnects do not kill ~srun~. Skip ~linux-rg~ entirely
for this pass; Terra boots on stock ~linux~ / ~linux-lts~.

Artifact layout sized for a 16GB USB target (keep the final ISO under ~14GB~):

| Path on elja (example) | Role |
| ~$SCRATCH/hz-build~ or ~$HOME/work/hz-build~ | Top-level work root |
| ~…/hzArchiso~ | This repository checkout |
| ~…/repo/hzarchiso~ | Custom pacman repo (~make aur-repo~ / ~file:///repo/hzarchiso~) |
| ~…/hzArchiso/out~ | ~mkarchiso~ ISO output; flash the ~.iso~ to the 16GB stick |

#+begin_src bash
# On login node: durable control plane
tmux new -s hziso || tmux attach -t hziso

# Interactive allocation (adjust partition/time/mem to site policy)
srun --pty --partition=128cpu_256mem --cpus-per-task=32 --mem=64G --time=12:00:00 bash

export HZ_ROOT="${SCRATCH:-$HOME}/hz-build"
export HZARCHISO_SRC="$HZ_ROOT/hzArchiso"
export REPO_HOST="$HZ_ROOT/repo/hzarchiso"
mkdir -p "$REPO_HOST"

cd "$HZARCHISO_SRC"
podman run --rm -it --privileged \
  -v "$HZARCHISO_SRC:/work:z" \
  -v "$REPO_HOST:/repo/hzarchiso:z" \
  -w /work \
  archlinux:base-devel \
  bash -lc '
    pacman -Sy --noconfirm archiso base-devel go jq make sudo git
    useradd -m builder
    printf "builder ALL=(ALL) NOPASSWD: ALL\n" >/etc/sudoers.d/builder
    chown -R builder:builder /repo/hzarchiso /work
    sudo -u builder HZARCHISO_INSTALL_BUILT=1 make aur-repo
    sudo -u builder make check
    make build
    ls -lh out/
  '
#+end_src

Optional later (~linux-rg~ only when an Arch container can finish ~makepkg~):
build packages from the ~linux-rg~ tree with ~LINUX_RG_PROFILE=rgam5terra~, copy
~linux-rg-*.pkg.tar.zst~ and ~linux-rg-headers-*.pkg.tar.zst~ into
~HZARCHISO_PREBUILT_DIR~, add those names to ~aurpkgs.txt~ and the Terra
installer kernel list, then re-run ~make aur-repo~ / ~make build~.

Flash example (on a machine with the stick attached; destructive):

#+begin_src bash
# Replace /dev/sdX after verifying with lsblk
sudo dd if=out/*.iso of=/dev/sdX bs=4M status=progress oflag=sync
#+end_src
